# India — GST & Statutory Understanding

Naffo's core skills are deliberately country-neutral. This skill adds the Indian
layer: how to read Naffo data through GST rules, which return each number belongs
to, and where the ERP stops and the GST portal begins.

**Load order:** `naffo-erp-guide` first (routing + safety), then this skill.

---

## Step 0 — Confirm this skill applies

```
naffo_get_my_profile
```

Check the org profile before using anything below:

| Signal | Meaning |
|---|---|
| `GSTIN` present | India GST registered → this skill applies |
| `PAN` / `TAN` present, no GSTIN | Indian entity, not GST registered → income-tax/TDS parts apply, GST parts don't |
| No Indian tax IDs | **Stop using this skill.** Use the country-neutral core skills |
| Currency / FY start | Use exactly what the profile returns — do not assume INR or April |

Never ask the user for their GSTIN or state — read it from the profile.

## The India facts that change how you read the data

### Financial year runs 1 April → 31 March

FY 2026-27 means 01-04-2026 to 31-03-2027. When a user says "this year",
"FY26", "last year", or "annual", resolve it to April–March dates before
calling any report tool — never to a January–December calendar year. Purchase
orders carry a `financialYearId`; take it from the ERP, never construct it.

### Intra-state vs inter-state decides the tax heads

| Supply | Tax heads |
|---|---|
| Within the same state (place of supply = supplier's state) | CGST + SGST |
| Across states, or to/from a UT | IGST |
| Export / SEZ | Zero-rated — treatment differs, flag for the CA |

The party's state comes from the **first two digits of their GSTIN** (state
code). If a counterparty's GSTIN is missing, say the head split can't be
determined rather than guessing.

### Rate slabs after GST 2.0 (effective 22 September 2025)

Live slabs are **0%, 5%, 18%, and 40%** (demerit). The old 12% and 28% slabs
were withdrawn.

**Never compute or assume a rate.** Read the rate off the invoice line or the
item master and present it as returned. If a user asks "what GST applies to X",
answer from the item master, and if it isn't there, say so and point them to
their CA — a wrong slab creates a wrong return.

Dairy and agri are exactly where guessing goes wrong: fresh/loose milk,
packaged milk, curd, paneer, ghee, and flavoured milk do not all sit in one
slab. Always resolve the item first with `naffo_search_item` and read its rate.

### GSTIN, HSN, SAC

- GSTIN: 15 characters — 2-digit state code, 10-character PAN, entity code, `Z`, checksum.
- HSN classifies **goods**; SAC classifies **services**.
- HSN digit depth reported in GSTR-1 scales with turnover (more digits at higher
  AATO). Report the codes stored on the item; never invent or pad a code.

## Return map — which Naffo report feeds which return

```
naffo_get_gstr1_summary({ fromDate, toDate })   → outward supplies (sales)
naffo_get_gstr2_summary({ fromDate, toDate })   → inward supplies (purchases / ITC side)
```

| Return | What it is | Fed by |
|---|---|---|
| **GSTR-1** | Outward supply detail | `naffo_get_gstr1_summary`, cross-checked against `naffo_list_sale_invoices` |
| **GSTR-2B** | Auto-drafted ITC statement generated by the portal | Reconcile against `naffo_get_gstr2_summary` + `naffo_list_purchase_invoices` |
| **GSTR-3B** | Monthly summary + tax payment | Derived from the two above; verify against `naffo_get_trial_balance` tax ledgers |
| **GSTR-7 / GSTR-8** | GST TDS / TCS by deductors and e-commerce operators | Applies only if registered as such |
| **GSTR-9 / 9C** | Annual return / reconciliation | Full-FY runs of the above |
| **CMP-08** | Composition scheme quarterly statement | Only for composition dealers — no ITC, different rate logic |

Typical monthly rhythm: GSTR-1 around the 11th, GSTR-3B around the 20th, GST
TDS/TCS returns around the 10th, with a separate quarterly (QRMP) track whose
GSTR-3B date differs by state group.

> **Dates and thresholds move.** CBIC extends due dates by notification, and the
> portal now blocks returns filed more than three years late. State the ERP
> numbers precisely; for the applicable date, tell the user to confirm on the GST
> portal or with their CA. Never present a filing date as certain.

### Reading invoice status

`naffo_list_sale_invoices` and `naffo_list_purchase_invoices` accept
`status: GST_FILED`. Treat `GST_FILED` as "already reported in a filed return" —
so a correction to one of those invoices is an amendment question, not an edit.
Flag it and stop rather than silently editing a filed period.

## ITC discipline

1. ITC belongs to the buyer only when the invoice actually appears in **GSTR-2B**. A
   purchase sitting in Naffo but missing from GSTR-2B is a supplier-filing problem,
   not a claimable credit.
2. Reconcile in this order: `naffo_get_gstr2_summary` → `naffo_list_purchase_invoices`
   for the same period → list the differences by vendor.
3. Report three buckets: **in both**, **in Naffo only** (chase the vendor / hold the
   credit), **in GSTR-2B only** (missing purchase entry — record it).
4. Blocked credits, common-credit apportionment, and reversal rules exist and are
   fact-specific. Surface the exposure; don't rule on it.
5. Reverse charge (RCM): the recipient pays the tax and claims credit separately.
   If a vendor bill looks like an RCM case, say so and let the user confirm.

## Where the ERP stops

Naffo's MCP catalog exposes **no e-invoice (IRN), e-way bill, or income-tax TDS
filing tools.** So:

- **E-invoice / IRN:** applies above the notified turnover threshold (₹5 crore AATO
  at the time of writing). Naffo does not mint IRNs — never claim an invoice "has
  an IRN". Tell the user to generate it on the IRP.
- **E-way bill:** required for goods movement above the notified consignment value
  (commonly ₹50,000, with state variations). `naffo_create_delivery_challan`
  records vehicle number, driver, and dispatch time — useful supporting data, but
  it is not an e-way bill.
- **Income-tax TDS/TCS:** section 194Q (buyer TDS on large purchases), 206C(1H)
  (seller TCS), 194C/194J/194H on expenses. Naffo records the ledger entries;
  rates, thresholds, and challans belong to the CA and the TRACES/IT portal.
  Read the ledger with `naffo_get_ledger_statement`, don't compute the liability.

## Indian seasonality

For demand and cash planning, the Indian calendar matters more than the Gregorian one:

- `naffo_get_demand_features` returns `is_wedding_season` and `is_harvest_season`
  flags, and marks `demand_pattern: FESTIVAL_DRIVEN` where it applies.
- Diwali, Navratri, Holi, Eid, Ganesh Chaturthi, Onam, and Pongal drive sweets,
  dairy, and gifting demand; Shraadh/Chaturmas periods suppress it.
- Q4 (Jan–Mar) carries year-end pressure: collections push, stock counts, and the
  FY cut-off.

Use `seasonal-patterns` for the index and `naffo-optimization` for the
forecast-to-order chain. Label a peak only when the tool data shows one.

## Presenting numbers

- Currency symbol `₹`, Indian digit grouping: `₹12,34,567.89`, not `₹1,234,567.89`.
- Lakh = 1,00,000; crore = 1,00,00,000. Mirror the unit the user used.
- **Never re-round or re-derive a tool number.** If a total must be shown in crore,
  show the exact figure alongside it.
- Reply in the user's language — English, Hindi, Gujarati, or Hinglish.

## Hard boundaries

- This skill explains how to read Naffo data under Indian rules. It is **not tax
  or legal advice.** Rates, due dates, thresholds, and eligibility change; route
  those to the user's CA or the GST portal.
- Every number comes from a tool call. No estimated GST, no assumed slab, no
  invented GSTIN, HSN, IRN, or challan number.
- Financial writes still follow the core rule: resolve → show the user → explicit
  confirmation → write with `idempotencyKey`.
- Never edit or re-post an invoice in a period already filed. Flag it as an
  amendment and stop.
